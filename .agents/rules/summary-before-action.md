# Rule: Core Summary & Explicit Confirmation Before Implementation

## Core Principle
Whenever the user provides any input, requirement, feature request, or problem description:
1. **DO NOT** jump straight into coding, file generation, building, or execution.
2. **ALWAYS** present a clear, high-level core summary first (মূল সারসংক্ষেপ ও পরিকল্পনা).
3. **WAIT** for the user's explicit approval or instructions before executing the plan.

## Required Workflow
1. **Analyze & Summarize First**:
   - Provide a concise Bengali/English summary outlining:
     - **Objective & Scope**: What needs to be done.
     - **Implementation Strategy**: Key approach, steps, and expected outcomes.
     - **Important Decisions / Options**: If any trade-offs or choices exist.
2. **Request Confirmation**:
   - Clearly ask for user confirmation before starting development.
3. **Execute Only on User Consent**:
   - Begin development, file editing, or build commands only after the user responds with approval (e.g., 'কাজ শুরু করো', 'Build করো', 'Proceed').
